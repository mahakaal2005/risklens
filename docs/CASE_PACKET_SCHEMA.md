# Case Packet Schema — ClearRisk Recover

Status: Implemented, Milestone 4. Generated by `ml/case_packet.py::build_case_packet()`. **This is an in-memory/JSON demonstration artifact only — it does not create a real case in a database, and no action is taken against any merchant.**

Every field below is labeled with its visibility class:

- **analyst-only** — shown to the payment-risk analyst/reviewer; never shown to the merchant.
- **merchant-safe** — safe to show to the merchant directly.
- **internal metadata** — technical/versioning detail, not narrative text; typically shown alongside the analyst view, never shown as merchant-facing narrative.
- **audit-preview only** — a structured event object marked explicitly as a preview, not a persisted record (no database or audit log exists yet — see Milestone 10 in `docs/IMPLEMENTATION_PLAN.md`).

## 1. `identification`

| Field | Visibility | Description |
|---|---|---|
| `case_preview_id` | internal metadata | Deterministic hash of `merchant_id:week_start`, prefixed `case_preview_`. Not a real case ID (no case table exists yet). |
| `merchant_id` | internal metadata | The merchant token. Present here as a record identifier; never inserted into analyst or merchant-safe explanation *text*. |
| `week_start` | internal metadata | The merchant-week being assessed. |
| `generated_at` | internal metadata | UTC timestamp the packet was generated. |
| `synthetic_data_notice` | merchant-safe | Fixed notice: this packet describes synthetic, demonstration-only data. |

## 2. `assessment`

| Field | Visibility | Description |
|---|---|---|
| `model_probability` | analyst-only | The Logistic Regression model's raw probability (`null` in degraded mode). |
| `selected_threshold` | analyst-only | The validation-selected operating threshold (0.10 as of Milestone 3). |
| `risk_signal_intensity` | analyst-only (safe to summarize as a category to the merchant, but the field itself is analyst-facing) | Low / Medium / High, from `ml/model_utils.py::combined_policy()`. |
| `rules_only_score` | analyst-only | The 0-100 rules-only severity score. |
| `triggered_rules` | analyst-only | List of triggered rule IDs. |
| `recommendation` | analyst-only (the *category* is echoed merchant-safe, not this exact enum value) | One of the five allowed recommendations. |
| `policy_explanation` | analyst-only | Why this recommendation was chosen — required whenever the numeric intensity and the recommendation could otherwise look inconsistent (see Milestone 2/3's "high tier ≠ automatic manual review" rule). |
| `model_version` | internal metadata | e.g. `0.1.0`. |
| `rules_version` | internal metadata | e.g. `0.2.0`, from `rules/risk_rules.yaml`. |
| `degraded_mode` | internal metadata | `true` if the ML model was unavailable and this packet used rules-only. |

## 3. `analyst_explanation`

| Field | Visibility | Description |
|---|---|---|
| `summary` | analyst-only | ≤4-sentence deterministic summary. |
| `top_model_factors` | analyst-only | Ranked list of `{feature, contribution, sentence}`, computed directly from the fitted Logistic Regression coefficients × each row's transformed feature value. Empty in degraded mode. |
| `triggered_rule_explanations` | analyst-only | Per-rule `{rule_id, severity, explanation}` with concrete before/after values. |
| `trend_values` | analyst-only | Refund/chargeback/volume current-vs-prior, evidence coverage, support ticket rate, support resolution time. |
| `uncertainty_statement` | analyst-only | Fixed honesty statement — never omitted, even at low risk (a low score is not a guarantee; see the early-hidden-risk demo case). |

## 4. `merchant_safe_explanation`

| Field | Visibility | Description |
|---|---|---|
| `reason_category` | merchant-safe | A general category (e.g. "refund pattern review"), never the internal rule ID. |
| `review_signal_statement` | merchant-safe | Fixed statement: this is a review signal, not a fraud finding, and no action has been taken. |
| `reasons` | merchant-safe | The triggered rules' own `merchant_safe_explanation` text — no numbers, no thresholds. |
| `suggested_evidence` | merchant-safe | Tailored checklist (see Section 5). |
| `appeal_placeholder` | merchant-safe | Placeholder text; the real appeal flow is not implemented until a later milestone. |

**Never present in this section:** raw model probability, exact threshold values, model coefficients, latent-state names, the future label, or the phrase "fraud confirmed" (enforced by `ml/case_packet.py::_assert_packet_is_safe()`, which raises if any forbidden term appears).

## 5. `evidence_checklist`

merchant-safe. Tailored to which rules triggered — see `ml/case_packet.py::EVIDENCE_ITEMS_BY_RULE`:

| Triggered rule | Evidence items added |
|---|---|
| `REFUND_RATE_SPIKE` | Recent refund/cancellation records; explanation for recent product/pricing/listing changes |
| `CHARGEBACK_RATE_SPIKE` | Chargeback/dispute reason breakdown; proof of delivery or service fulfilment |
| `EVIDENCE_COVERAGE_GAP` | Fulfilment/delivery proof for a sample of disputed orders |
| `SUPPORT_OPERATIONAL_STRESS` | Customer-support response records; plan to address recurring operational issues |
| `COMBINED_LOSS_SIGNAL` | Plan to address recurring operational issues |
| (any triggered rule + `|transaction_volume_change| >= 0.30`) | Explanation for the recent transaction-volume change |

A merchant-week with no triggered rules gets an empty checklist — evidence is never requested without a reason.

## 6. `audit_preview_events`

audit-preview only. Every event includes `event_type`, `timestamp`, `preview_only: true`, and a `note` stating it is not persisted.

| Event | When generated |
|---|---|
| `ASSESSMENT_GENERATED` | Always |
| `EXPLANATION_GENERATED` | Always |
| `REVIEW_CASE_RECOMMENDED` | Recommendation is not `APPROVE` |
| `EVIDENCE_REQUEST_RECOMMENDED` | Recommendation is `REQUEST_EVIDENCE` |
| `MANUAL_REVIEW_RECOMMENDED` | Recommendation is `MANUAL_REVIEW_REQUIRED` |
| `ESCALATION_RECOMMENDED` | Recommendation is `ESCALATE_TO_COMPLIANCE` (an addition beyond the literal Milestone 4 list, for completeness with the fifth allowed recommendation) |

## Optional: `prior_simulated_review_context`

internal metadata / analyst-only, only present if passed to `build_case_packet()`. Not populated by `ml/generate_demo_cases.py` in this milestone (no review-case history exists yet).

## What is always excluded

`label_high_loss_next_30d` and `latent_state_for_demo_only` are never read as meaningful input by `build_case_packet()` (stripped defensively even if present on the input record) and are asserted absent from the serialized packet JSON by `_assert_packet_is_safe()`. `merchant_id` appears only as an identification field, never interpolated into analyst or merchant-safe narrative sentences.
