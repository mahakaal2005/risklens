# demo_data/

**All contents of this directory are synthetic and demonstration-only.** Nothing here represents a real merchant, real transaction, or real payment outcome.

## Files

- `synthetic_merchant_week_data.csv` — the generated merchant-week dataset. One row per merchant per week (`merchant_id` + `week_start`). Generated by `ml/generate_synthetic_data.py`. See `DATA_DICTIONARY.md` for the field-by-field schema and `MODEL_CARD.md` for the 5-state latent-merchant simulation that produced it.
- `synthetic_data_metadata.json` — generation metadata for the CSV above: seed, generation timestamp, merchant/row counts, date range, latent-state distribution, label distribution, and generator version. Regenerated alongside the CSV every time the generator runs.

## How to regenerate

```bash
python3 ml/generate_synthetic_data.py
```

Optional flags: `--seed`, `--n-merchants`, `--n-weeks`, `--start-date`, `--output-csv`, `--output-metadata`. Default seed is `42`; the same seed always reproduces the same dataset.

## Important notes

- `latent_state_for_demo_only` is included for demonstration and evaluation purposes (e.g. verifying false-positive/false-negative opportunities exist). **It must never be used as a model feature** — it is not observable in a real deployment and using it would make evaluation circular.
- `label_high_loss_next_30d` is generated from the hidden latent state's own probability distribution, not from a threshold on the observed refund/chargeback fields — see `MODEL_CARD.md`'s "Latent-state synthetic-data design" section for why this matters.
- Regenerating with a different seed, merchant count, or week count will overwrite these files. If you need to preserve a specific run for comparison, copy it elsewhere first.
